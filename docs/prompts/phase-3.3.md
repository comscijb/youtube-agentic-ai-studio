## A. Always 16:9 shots

- Default `IMAGEGEN_LATENT_SOURCE = "empty_16x9"` for all reference-conditioned shots (keep
  `reference` as an option for edit-like uses). Include the latent source in the cache key so the
  three square shots regenerate.
- Aspect-ratio guard on every shot/thumbnail output: if the decoded image is not within 2 % of the
  requested ratio, **do not crop** — regenerate once with `empty_16x9`; if still wrong, fail the shot
  with a clear message. Remove any silent center-crop of shots (border-crop from 3.2.1 stays, but
  must keep 16:9 and never cut more than 6 % per side; otherwise regenerate).
- Character/location references keep their own sizes; only the output latent controls the frame.
- Tests: first reference square + `empty_16x9` → 16:9 request; non-16:9 output → regenerate, never crop.

## B. Art-direction fixes (identity, visual bible rules, shot prompts)

- **Dread comes from light, shadow, scale and stillness — never from decay, dirt, damage or
  injury** unless the screenplay states it. Settings keep the social status the story gives them
  (Julian's loft is immaculate, expensive, minimal: polished surfaces, precise objects, pristine
  walls). Replace any wording that invites grime, rot, stains or ruin.
- Crimson accent examples: wine, a ring, a scarf, a candle reflection. **Remove "wound"**; no
  injuries, blood, scratches or bruises unless the scene's narration explicitly contains them
  (check the shot's `narration_excerpt`; add a code check rejecting `blood`, `wound`, `scratch`,
  `bruise`, `injur*`, `cut on` in shot prompts when the excerpt doesn't mention them).
- **Wardrobe and grooming follow the visual bible per scene** and the narration's emotional state at
  that moment (Elena in s01 is poised and composed, not dishevelled; tears only where the text has
  them). Include wardrobe + grooming in every character shot prompt.
- **Background figures only when the narration places them there.** Shots in scenes/times without
  guests must not contain extra people; add an explicit "no other people present" phrasing (positive:
  "the two of them alone in the room") and a planner rule tied to the scene's chronology.
- Re-run only the shot list prompt rules; existing approved character, location and style
  references stay valid (don't bump their style hash for this change; bump only the shot-prompt version
  so shots regenerate).

## C. Stock imagery: off by default, opt-in checkbox

- New `STOCK_ENABLED = False` (config + `.env.example`); when false, **no** Pixabay/Openverse request
  is ever made in any mode (photo or illustration), and preflight doesn't require stock keys.
- In the GUI, the "Images" step means **shot generation** (visual bible → shot list → ComfyUI). Add a
  checkbox in Settings: "Usar banco de imagens (Pixabay/Openverse) como fallback" (default off).
  When on, stock is only used in `cinematic_photo` mode or as a last resort for environment/object
  shots after generation retries, and it's recorded in the manifest.
- Keep the stock code and tests; add tests that nothing calls stock when disabled.

## D. Projects: continue work in progress

Today everything lives in a single `output/` and the GUI expects a fresh run. Introduce projects:

- **Layout:** `projects/<slug>/` (slug from title + date, e.g.
  `2026-10-23-the-man-who-needed-everyone-to-envy-him`) containing the same artifact names used in
  `output/` today (brief, bible, outline, script, review, narration, visual bible, shot list,
  images/shots, video, thumbnail, approvals, checkpoints, debug), plus `project.json`
  (title, created/updated, status per stage, video_type, target duration, published video id if any).
  Shared, channel-wide assets stay outside (`assets/style_refs`, `music library`, `data/`).
  Character/location refs are per project.
- **Migration:** `python -m scripts.migrate_output_to_project` moves the current `output/` content
  (except `benchmarks/` and archives) into a new project folder; dry-run first; never deletes, it
  moves and leaves a `output/MIGRATED.txt` pointer. Benchmarks keep their own folder.
- **Config:** replace hard-coded `config.OUTPUT_DIR` usage with an active-project directory resolved
  at runtime (`--project <slug>` on every script; GUI selection; fallback to the most recent project).
  Keep `output/` working as a legacy project path for tests and old scripts during the transition.
- **Stage status** computed from the artifacts present and their `source_hash` chain: `done`,
  `stale` (an upstream artifact changed), `partial` (e.g. shots 5/50), `missing`. Show the next
  recommended step.
- **GUI:**
  - Home screen with two actions: **"Novo projeto"** (current flow) and **"Continuar projeto"**
    (list of projects with title, date, thumbnail if present, stage badges and next step).
  - Opening a project shows each stage with **Run / Re-run / Skip**, respects existing artifacts and
    checkpoints, and never forces the Story Brief step. Running a later stage on a stale upstream
    warns and offers to re-run upstream.
  - Approvals (character/location refs, style anchors, review gate) open within the project.
  - Upload/publication ledger records the project slug.
- **CLI:** `python -m scripts.project list | show <slug> | open <slug>` (open = set active).
- Tests: status computation (done/stale/partial/missing), migration dry-run and move, scripts honour
  `--project`, GUI endpoints for list/open/stage run (Flask test client), legacy `output/` still works.
